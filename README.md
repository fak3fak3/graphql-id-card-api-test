# graphql id card

цифровая визитка: graphql api — профиль, навыки, опыт, проекты

стек: ts, node 24, nestjs 12, apollo server 5, prisma 7, postgres 18, docker

## запуск

```bash
docker compose up --build
```

открыть http://localhost:3000/graphql — там apollo sandbox с готовым запросом

`.env` не нужен, база сама создается, мигрируется и заполняется

## принятые решения

### структура

- три слоя: resolver → service → repository; prisma есть только в repository
- модели graphql отдельно от моделей prisma, поля маппятся явно
- каждая секция визитки — свой модуль. `Profile.skills` объявлен в модуле skills, а не в profile
- без мутаций: данные идут из сида, а crud без авторизации — дыра

### вложенные данные, n+1

- на каждую связь dataloader: все обращения за один уровень запроса уходят одним `WHERE ... IN (...)`
- число sql-запросов не зависит от количества строк: запрос из тз — 4, вся визитка — 8; проверяется тестами (`test/query-count.e2e-spec.ts`)
- грузится только то, что попросили: `profile { name }` — один запрос
- глубина запроса ограничена: в схеме цикл навыки ↔ проекты

### база

- достижения — отдельная таблица, а не массив строк: так есть второй уровень вложенности
- проекты и навыки — many-to-many, связь работает в обе стороны
- период работы — две даты; строка периода и длительность считаются в коде, не хранятся

### миграции и сид

- порядок старта: db → migrate → app
- миграции и сид — отдельный одноразовый контейнер, а не entrypoint приложения: рестарт апки их не гоняет заново
- сид идемпотентный: фиксированные id и upsert в одной транзакции, повторный запуск дублей не дает

### остальное

- язык данных один — русский; код, схема и ошибки на английском
